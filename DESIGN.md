# Interview Practice design

The study screen answers one question: what decision would you make with the system’s current constraints? The current prompt is the primary task. The architecture explains the same stage, and grows only when its answer is revealed.

Use a flat black ground, #111 surfaces, #2a2a2a nested controls, #fff primary text, #b4b4b4 secondary text, and #949494 metadata. Use IBM Plex Sans at 400, 500, and 600. A muted mint marks changed architecture components; official service icons identify AWS products. Primary actions use white with black text. Keep controls at least 44px tall, panels unshadowed, and body text readable.

The workspace uses the full browser width and available height. A compact text header holds the scenario title and session controls without a logo or separate masthead. Desktop pairs a readable question column with a diagram that fills the remaining space. Tablet stacks them. Phone diagrams use a vertical arrangement with numbered connections and a matching text list. Expanded diagrams have button-operated zoom and component descriptions. Notes are optional. Native dialogs retain keyboard focus and support Escape. Reduced motion disables transitions.

Only revealed questions belong in the session path. Render diagrams from the active question or answer frame; do not reserve positions, labels, edges, or thumbnails for future changes. Authored positions stay stable as the design grows. Larger inline diagrams focus on the relevant established subsystem, with a numbered connection list and a count of its established components. The expanded view always includes the full current frame and readable component descriptions. A reference design is one valid approach and is never described as a company’s actual production architecture.

History preserves completed paths, notes, and self-ratings across new sessions. Its dialog shows only answered questions, and unmounts those records when closed so practice does not preview previous branches. Sessions retain their content revision: adding follow-ups cannot reopen an earlier completion. Earlier local saves and backups migrate without resetting their question or reveal phase. Pending sync requests retain their original payload for idempotent retries.

The two food-delivery variants each contain nine authored questions. New sessions avoid the latest starting variant. Follow-ups are chosen only from the current question’s valid children, avoiding the previous continuation when alternatives exist and weighting due, weak, and unseen questions. Selection happens when continuing; the saved path never rerolls on reload. Every nonterminal offers at least two continuations, and each child explicitly continues its parent’s reference design. Each question still has its own FSRS schedule.

The mode bar holds Scenarios, Daily review, and Private cards, with quiet account and backup controls. Daily counts are plain numbers derived from actual reviews, with no streaks or invented progress. A review fixes its queue when it begins, puts due questions first, and introduces at most five new items per study day. FSRS-6 uses a 90% recall target. Only rated scenario questions can enter daily review; their reference architecture still waits for reveal.

Private editing uses labeled 48px fields, preserved local drafts, and one explicit save action. Native backup dialogs preview an import before replacing the workspace and offer undo during that page visit. Account loading has a plain status; failed sync keeps the exact local draft and retry request. Concurrent edits show both choices explicitly, with a download action before choosing. Guest and account caches remain separate, including on sign-out. Mint remains reserved for diagram changes and focus rather than navigation or rating buttons.
